# TMS 최적 배송코스 · 카카오맵

카카오맵 기반 배송경로 최적화 도구. **단일 HTML 파일**로 동작하며, 차량 1대의 단순 순회(TSP)부터
납품처별 시간창·적재용량·고정순번·운행시간 제약을 모두 반영한 다차량 배차(CVRPTW)까지
**옵션 토글만으로** 단계적으로 확장됩니다.

```
index.html                 ← 앱 본체 (자체 완결형)
tools/dev-server.mjs       ← 개발 서버: 정적 서빙 + 같은 오리진 길찾기 프록시 (의존성 없음)
tools/kakao-proxy.mjs      ← 별도 CORS 프록시 (다른 정적 서버를 쓸 때만)
start.sh / start.bat       ← 더블클릭 실행
.env.example               ← REST 키를 서버에만 보관하고 싶을 때
samples/sample-stops.csv   ← 샘플 납품처 15곳
docs/DESIGN.md             ← 구현계획 · 설계 문서
```

---

## 1. 빠른 시작

### ⓪ 그냥 열어보기 (설치·키 없이)

`index.html` 을 브라우저로 **더블클릭**하면 바로 동작합니다. 샘플 납품처 15곳이 들어 있어
[최적화 실행]만 누르면 됩니다. 카카오 지도 타일 대신 **좌표 기반 간이 지도**가 뜨지만,
최적화 엔진·타임라인·순서표·CSV 내보내기는 완전히 동작합니다.

> 실제 지도와 실제 도로거리를 쓰려면 아래 ①~③을 따라가세요.

---

### ① 개발 서버 실행 (명령 하나)

```bash
node tools/dev-server.mjs      # 또는 npm start
```

Windows 는 **`start.bat` 더블클릭**, macOS·Linux 는 **`start.sh` 더블클릭**으로도 됩니다.
Node.js 가 없으면 안내 메시지가 뜹니다 ([nodejs.org](https://nodejs.org) LTS 설치).

실행하면 이런 배너가 뜹니다.

```
╔════════════════════════════════════════════════════════════════╗
║  TMS 배송코스 최적화 · 개발 서버                               ║
╠════════════════════════════════════════════════════════════════╣
║  앱 주소   http://localhost:3000                               ║
║                                                                ║
║  ▸ 카카오 디벨로퍼스에 등록할 사이트 도메인                    ║
║      http://localhost:3000                                     ║
║      내 애플리케이션 → 앱 설정 → 플랫폼 → Web                  ║
╚════════════════════════════════════════════════════════════════╝
```

**이 개발 서버가 앱과 길찾기 API 를 같은 오리진으로 묶습니다.** 그래서 CORS 가 아예
발생하지 않고 별도 프록시도 필요 없습니다. 포트가 사용 중이면 자동으로 다음 포트를 쓰고,
등록해야 할 주소를 그때 다시 알려줍니다.

### ② 브라우저로 열고 [설정] 탭

표시된 주소를 열면 **설정 마법사**가 3단계로 안내합니다. 각 단계는 **실제로 호출해서**
되는지 확인하므로, 통과하면 진짜로 동작하는 것입니다.

| 단계 | 넣는 것 | 확인 방법 |
|---|---|---|
| 1 · 실행 환경 | — | 개발 서버 감지 + **등록할 도메인을 복사 버튼과 함께** 표시 |
| 2 · 지도·주소검색 | **JavaScript 키** | SDK 로드 → 지도 생성 → 주소검색 1회 실호출 |
| 3 · 실제 도로거리 | **REST API 키** | 서울역→강남역 길찾기 실호출 → **실제 거리·시간 표시** |

2단계가 실패하면 *앱키가 틀렸는지* / *도메인 등록을 안 했는지* 를 구분해 알려주고,
3단계가 실패하면 카카오가 보낸 오류 메시지를 그대로 보여줍니다.

### ③ 키 발급

[카카오 디벨로퍼스](https://developers.kakao.com) → 내 애플리케이션에서 두 키를 받습니다.
**서로 다른 키이니 헷갈리지 마세요.**

| 키 | 메뉴 | 쓰임 |
|---|---|---|
| **JavaScript 키** | 앱 설정 → 앱 키 | 지도 표시, 장소·주소 검색 |
| **REST API 키** | 앱 설정 → 앱 키 | 실제 도로거리 길찾기 |

**필수**: [앱 설정 → 플랫폼 → Web] 에 ①에서 표시된 주소(`http://localhost:3000`)를
**그대로** 등록해야 지도가 뜹니다. 포트까지 정확히 일치해야 합니다.

> 길찾기 API 는 카카오모빌리티 소관이라 별도 이용 신청이 필요할 수 있습니다. 3단계에서
> 권한 오류가 나면 [카카오모빌리티 디벨로퍼스](https://developers.kakaomobility.com) 에서
> 길찾기 API 신청 상태를 확인하세요.
>
> ⚠️ 이 저장소를 만든 환경에서는 카카오 도메인이 네트워크 차단되어 있어, **실제 발급 키로는
> 검증하지 못했습니다.** 모의 서버로 전 구간을 테스트했지만 최초 실검증은 사용자 몫입니다.

### REST 키를 브라우저에 넣고 싶지 않다면

`.env.example` 을 `.env` 로 복사하고 키를 넣으면 **서버에만 보관**되어 브라우저에
노출되지 않습니다. 값을 바꾸면 서버 재시작 없이 바로 반영됩니다.

```bash
cp .env.example .env        # Windows: copy .env.example .env
# .env 안에서 KAKAO_REST_KEY=발급받은_키
```

공용 PC 라면 이 방식을 쓰세요. `.env` 는 `.gitignore` 에 있어 커밋되지 않습니다.

## 2. 납품처 입력 4가지 방법

| 방법 | 설명 |
|---|---|
| **장소·주소 검색** | 카카오 검색으로 좌표 자동 확보 |
| **지도에서 찍기** | 지도를 클릭해 좌표 지정, 주소는 역지오코딩 |
| **CSV·엑셀 붙여넣기** | 엑셀에서 복사(탭 구분)하거나 CSV 붙여넣기. 좌표가 없으면 주소로 자동 지오코딩 |
| **수기 입력 폼** | 물량·시간창·순번 제약까지 한 화면에서 |

```
서울역점,서울 중구 한강대로 405,37.5547,126.9707,320,1.2,18,08:00,11:00,15,1,

```

## 3. 제약조건 옵션

옵션 탭에서 켜고 끄는 것만으로 문제 유형이 바뀝니다.

| 옵션 | 내용 |
|---|---|
| **납품 가능 시간창** | 납품처별 시작·종료 시각. 지각은 위반으로 표시 |
| **적재 용량** | 차량별 중량(kg)·부피(CBM)·박스 한도 |
| **고정 순번 · 우선순위** | "반드시 첫 번째/마지막", 우선순위 역전 방지 |
| **하역시간 반영** | 납품처별 하차·검수 소요시간을 일정에 포함 |
| **차량 운행시간 한도** | 1대당 최대 운행시간 + 운행 종료시각 |
| **차고지 복귀** | 마지막 납품 후 복귀 구간까지 계산 |
| **조기 도착 시 대기 허용** | 시간창 시작 전 도착 시 대기 (끄면 위반 처리) |
| **차량 간 물량 균등화** | 특정 차량 쏠림 방지 |

**제약 처리 방식**
- `유연(soft)` — 위반에 벌점을 물리되 해를 허용. **항상 결과가 나오고**, 무엇이 얼마나 위반됐는지 보여줍니다.
- `엄격(hard)` — 위반을 늘리는 이동을 아예 배제. 제약이 빡빡하면 좋은 해를 못 찾을 수 있습니다.

### 결정론적 실행

기본값 **켜짐**. 반복 횟수를 시계가 아닌 입력값으로 고정하므로 **같은 조건·같은 시드면 항상 같은
배차**가 나옵니다. 배차 결과를 재현·검증해야 하는 실무에서는 켜 두세요. 끄면 주어진 시간을 끝까지
써서 해 품질이 조금 올라가지만, 실행할 때마다 결과가 달라집니다.

## 4. 알고리즘

```
① 거리행렬   카카오모빌리티 1:N 길찾기(30개/요청) → 실패 구간 개별 보정 → 직선거리 폴백
             + localStorage 캐시로 재최적화 시 무호출
② 초기해     Clarke-Wright Savings (용량·차량지정 인지)
③ 개선       Simulated Annealing + relocate / swap / 2-opt / or-opt / 2-opt*
④ 다듬기     개선만 수용하는 하강 탐색
⑤ 복구       고정 순번(first/last) 강제 재배치
⑥ 실경로     차량별 다중 경유지 길찾기 → 실제 도로 폴리라인
```

모든 제약은 **미터 환산 페널티**로 단일 비용에 합산됩니다. 옵션 토글이 곧 가중치 on/off이므로,
같은 엔진이 TSP부터 CVRPTW까지 커버합니다. 자세한 내용은 [`docs/DESIGN.md`](docs/DESIGN.md).

> 휴리스틱이므로 **전역 최적해를 보장하지 않습니다.** 탐색 예산을 늘리면 해 품질이 올라갑니다.
> 납품처 30곳 이상이면 8초 이상을 권장합니다.

## 5. 결과 보기

- **지도** — 차량별 색상·선패턴 경로, 방문 순번 마커, 위반 지점 경고 배지
  (앱키가 없으면 좌표 기반 **간이 지도**로 자동 대체 — 상대 위치·경로·축척 표시)
- **배송 타임라인** — 차량별 간트 차트. 이동/대기/하역 구분, 시간창 배경 밴드로 위반이 한눈에
- **배송 순서표** — 도착·출발·구간거리·누적거리·적재·위반 사유
- **CSV 내보내기** — 기사 배포용 배송 지시서 (엑셀에서 바로 열리는 UTF-8 BOM)

차량 식별색은 색각 이상 검증(OKLab ΔE, all-pairs)을 통과한 4색만 사용하고, 5대 이상은 색을 늘리는
대신 **선 패턴(실선/파선/점선)** 을 곱해 최대 12대를 구분합니다. 방문 순번 배지·범례·결과표가 항상
함께 제공되므로 색상 단독으로 의미를 전달하지 않습니다.

## 7. 알려진 제약

1. 카카오맵 JS SDK는 **도메인 등록 필수** — `file://` 로는 지도가 뜨지 않습니다(간이 지도로 대체).
   개발 서버로 띄우고 그 주소를 카카오에 등록하세요. 포트가 바뀌면 다시 등록해야 합니다.
2. 개발 서버는 **루프백(127.0.0.1)에만 바인딩**합니다. 같은 네트워크의 다른 기기에서는
   접속되지 않으며, 이는 REST 키를 보호하기 위한 의도된 제약입니다.
3. 카카오모빌리티 1:N 길찾기의 `radius` 상한은 10km 입니다. 그 밖의 구간은 개별 길찾기로
   보정하고, 그마저 실패하면 직선거리 추정치로 대체하며 **추정 구간 수를 UI에 명시**합니다.
4. 최적화는 휴리스틱이므로 **전역 최적해를 보장하지 않습니다.** 탐색 예산을 늘리면 해 품질이
   올라갑니다(납품처 30곳 이상이면 8초 이상 권장).
5. 실용 상한은 **차량 12대 · 납품처 200곳 내외**입니다.
6. 라이트 테마 전용입니다 ([`docs/DESIGN.md` §6.3](docs/DESIGN.md) 참고).
7. 데이터는 브라우저 localStorage 에만 저장됩니다. 공용 PC 에서는 REST 키를 앱에 넣지 말고
   `.env` 방식을 쓰세요. 설정 내보내기(JSON)에는 API 키가 포함되지 않습니다.
8. **카카오 실제 키로는 검증하지 못했습니다** — 이 저장소를 만든 환경에서 카카오 도메인이
   네트워크 차단되어 있었습니다. 모의 서버로 전 구간(키 검증 → 행렬 조회 → 폴리라인)을
   테스트했으므로 흐름은 맞지만, 실제 키로는 사용자가 처음 확인하게 됩니다.
